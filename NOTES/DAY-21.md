## Project

RAG Knowledge Assistant

## What I Built

I built a RAG-based application that answers questions using information from provided documents.

The project includes a RAG workflow involving:

Documents
→ Chunking
→ Embeddings
→ Vector Store
→ Retrieval
→ Context
→ LLM
→ Grounded Answer

## Problem

An AI application may need to answer questions using specific documents rather than relying only on general LLM knowledge.

RAG retrieves relevant information from the provided documents and gives it to the LLM as context.

## Challenge

RAG quality depends on multiple parts of the pipeline.

Important failure points include:

- Poor source documents
- Poor chunking
- Poor retrieval
- Unsupported generation
- Missing grounding rules

## What I Learned

RAG is not simply connecting an LLM to a document.

It is a complete pipeline involving data, processing, chunking, embeddings, retrieval, context, LLM, and grounded generation.

I also learned that the system should avoid presenting unsupported information as if it came from the provided documents.
